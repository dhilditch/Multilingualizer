Launching a multilingual Squarespace site is not the moment to discover that nobody has translated the validation messages, the French subdomain has no certificate or the order emails are still in English.

Use this checklist while the destination languages are private. The aim is not to tick every box quickly. It is to find the gaps before a visitor does.

## 1. Define the launch

- [ ] List the original language and every destination language.
- [ ] Record the business reason for each language.
- [ ] Name the person responsible for each translation.
- [ ] Name the person who approves product, policy and checkout wording.
- [ ] Decide which pages, products and services are in the first launch.
- [ ] Decide which content is deliberately excluded.
- [ ] Confirm the site is Squarespace 7.1 for the built-in Weglot integration, or document the general-integration route used for an older site.
- [ ] Confirm every destination language is private until testing is complete.

## 2. Clean the source site

- [ ] Finish important original-language pages.
- [ ] Remove demo pages, test products and placeholder text.
- [ ] Fix broken links and missing images.
- [ ] Make page titles and H1s clear before translating them.
- [ ] Remove duplicate pages that should not be indexed.
- [ ] List content generated by third-party blocks or scripts.
- [ ] List account, booking, checkout and email systems outside normal page content.

Translation reproduces source problems very efficiently. Fix the original first.

## 3. Estimate the translated-word requirement

- [ ] Count the public source content.
- [ ] Include products, blog posts, navigation and footer text.
- [ ] Allow for title tags, descriptions and image alt text.
- [ ] Include customer notification emails for a store.
- [ ] Multiply by the number of destination languages.
- [ ] Leave space for planned content.
- [ ] Generate or synchronise all intended URLs during the trial.
- [ ] Compare the Weglot dashboard count with the estimate.

Use the [Weglot pricing calculator for Squarespace](/weglot-pricing-calculator-squarespace/) before choosing annual billing.

## 4. Configure translated URLs

- [ ] Confirm a custom domain is connected.
- [ ] Identify the active DNS provider.
- [ ] Add the exact CNAME records supplied by Weglot.
- [ ] Wait for Weglot's DNS check to pass.
- [ ] Confirm SSL is valid on every language hostname.
- [ ] Open an inner page on every translated hostname.
- [ ] Confirm the switcher preserves the page path.
- [ ] Record who can edit DNS if an urgent rollback is needed.

See the [full Squarespace language subdomain guide](/weglot-language-subdomains-squarespace/) for the separate Squarespace-managed and externally managed routes.

## 5. Review the translations

- [ ] Review the homepage and main conversion page manually.
- [ ] Review product and service names.
- [ ] Review prices, units and delivery promises.
- [ ] Review guarantees, cancellation, returns and privacy text.
- [ ] Review buttons and calls to action.
- [ ] Review navigation and footer text.
- [ ] Review empty states and error messages.
- [ ] Review metadata and social-sharing text.
- [ ] Check names, trademarks and words that should not be translated.
- [ ] Ask a fluent reviewer to approve high-risk pages.

Machine translation is a starting point. Anything that can cause a purchase, complaint or legal misunderstanding needs human review.

## 6. Check Squarespace features outside the normal page

- [ ] Confirm whether the site uses Email Campaigns.
- [ ] Confirm whether it uses Acuity Scheduling.
- [ ] Test third-party blocks and widgets.
- [ ] Test Member Sites and gated content.
- [ ] Test customer login and password reset.
- [ ] Test chat, maps, reviews and donation tools.
- [ ] Record each item as translated, configured separately, accepted in one language or blocking.

Squarespace lists Email Campaigns, Acuity, third-party blocks, Member Sites and customer login screens as outside the Weglot integration. Read [what Weglot does not translate on Squarespace](/what-weglot-does-not-translate-squarespace/) before assuming an embed is covered.

## 7. Test forms

- [ ] Submit every important form in each language.
- [ ] Trigger required-field and invalid-input errors.
- [ ] Check placeholder and consent text.
- [ ] Check the success state.
- [ ] Check the visitor's confirmation email.
- [ ] Check the owner's notification.
- [ ] Test mobile keyboard and field layout.
- [ ] Add and retest narrow dynamic selectors where necessary.

## 8. Test ecommerce

- [ ] Check product titles, descriptions, variants and stock messages.
- [ ] Check regular and sale prices.
- [ ] Add and remove products from the cart.
- [ ] Test discount codes and their errors.
- [ ] Check tax, shipping and delivery wording.
- [ ] Complete a test order in each language.
- [ ] Check payment instructions.
- [ ] Check the confirmation page.
- [ ] Preview and receive customer notification emails.
- [ ] Test gift-card language behaviour if gift cards are sold.
- [ ] Check refund and cancellation communication.

Use the [Squarespace multilingual ecommerce guide](/squarespace-multilingual-ecommerce/) for the complete store process.

## 9. Audit multilingual SEO

- [ ] Each language version has a separate crawlable URL.
- [ ] Each page has a self-referencing canonical.
- [ ] Reciprocal `hreflang` values use the correct full paths.
- [ ] The original Squarespace page contains complete language references.
- [ ] The visible page language matches its target.
- [ ] Titles and descriptions are translated and useful.
- [ ] Internal links do not send visitors back to the wrong language unnecessarily.
- [ ] No destination language is blocked by robots, a password or a private setting at launch.
- [ ] Search Console monitoring is ready.

See the [Squarespace Weglot SEO guide](/squarespace-weglot-seo/) for the checks and common errors.

## 10. Check design, mobile and accessibility

- [ ] Longer translated headings do not overlap or truncate.
- [ ] Buttons fit their text.
- [ ] Navigation works at mobile widths.
- [ ] The language switcher is keyboard accessible.
- [ ] Focus states remain visible.
- [ ] Right-to-left languages are tested where used.
- [ ] Images have appropriate alternative text.
- [ ] Forms retain visible labels.
- [ ] Colour and icon meaning is not the only language cue.

## 11. Prepare measurement

- [ ] GA4 records page views on translated URLs.
- [ ] Search Console covers the translated hosts or URL structure.
- [ ] Form completions are tracked.
- [ ] Ecommerce events include the correct currency and product.
- [ ] Weglot affiliate and Multilingualizer product clicks are distinguishable on this marketing site.
- [ ] The launch date and exact changes are recorded.
- [ ] A 7-day technical check and 28-day performance review are scheduled.

## 12. Launch and monitor

- [ ] Make one destination language public first if the project is large.
- [ ] Clear the relevant caches.
- [ ] Test from a signed-out browser.
- [ ] Recheck DNS, SSL and core pages.
- [ ] Watch forms, orders and support messages.
- [ ] Check Search Console for crawl and canonical issues.
- [ ] Review Weglot word usage after crawlers visit the site.
- [ ] Keep a rollback route for broken language links or critical transaction problems.
