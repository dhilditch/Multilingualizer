To make a Weebly website multilingual, choose whether you'll maintain your own translations or use a managed translation service. Then test the published pages, language switcher and enquiry or buying journey. Translating the homepage doesn't prove that every connected screen is translated.

Check which editor you use first. These instructions concern the Weebly editor, not an assumption that a different Square website product has identical settings.

## Use Multilingualizer's documented Weebly setup

Our [Weebly installation guide](/support/how-to-add-the-multilingualizer-to-weebly-sites/) describes placing the generated code in **Settings → SEO → Header Code**. It also explains where to place the floating selector code. An Embed Code element on one page isn't the documented site-wide installation route.

Follow the account and language configuration instructions, then publish a test page. Keep your language order consistent. Don't assume a selector appears automatically: configure the selector you want using the [language-selector guide](/language-selector-configuration-and-customisation/).

For ordinary translated text, follow the [on-page translation instructions](/support/how-to-add-on-page-translations/). Short text can separate language versions with two full stops. Text blocks begin and end with four full stops, with two full stops between versions. The tool doesn't use invented `ml-en` and `ml-es` span classes as the standard authoring format.

## What about multilingual search traffic?

[Google recommends different URLs for different language versions](https://developers.google.com/search/docs/specialty/international/managing-multi-regional-sites). If search visibility in each language is a requirement, decide how your chosen workflow supplies those pages and how visitors navigate between them.

Same-page text switching and separate indexable language URLs aren't the same thing. Don't assume a language selector creates additional search landing pages.

## Test the full site before launch

Open the published site on desktop and mobile, then switch through each language. Check navigation, headings, images, buttons, forms and confirmation messages.

For a shop, also test product details, basket, checkout, account screens and order emails. Record which system owns each step. Don't treat text translated on a product page as proof that a hosted payment screen or email follows the same language.

For manual pages, repeat this check after changing the original content. Keep the translated versions and their navigation in the same review process.
