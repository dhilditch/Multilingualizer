# Problem

Travel businesses need language handling across accommodation, itineraries, enquiries, reviews and booking links. A translated homepage alone does not show whether the useful journey works.

# Evidence

- Eighteen current Squarespace sites with Multilingualizer detected were classified as travel and hospitality, belonging to 16 customers.
- Elfsight review and chat widgets were observed on multilingual travel sites, providing a relevant route into the widget guide.

# Existing URL decision

- Canonical URL: `/multilingual-squarespace-travel-examples/`.
- Competing internal URLs: none.
- Link to the existing Squarespace ecommerce guide where payment and checkout behaviour matters.

# Solution structure

1. Verify three to five public examples and every stated language.
2. Review room, itinerary or service pages plus the booking or enquiry hand-off.
3. Record language controls, currencies, reviews, chat and untranslated third-party screens.
4. Separate editor-managed content from booking-engine content.

# Product fit and CTA

- Multilingualizer for manually managed public Squarespace pages.
- Weglot where managed translation or separate language URLs are required.
- Elfsight only where a review or chat widget solves a visible requirement.

# Publication checks

- [ ] Verify every named site on desktop and mobile
- [ ] Follow one booking or enquiry journey per language
- [ ] No occupancy, conversion, revenue or satisfaction claim
- [ ] Offer a factual correction route
