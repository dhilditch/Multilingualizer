# Problem

A buyer needs the boundary list before paying, plus practical tests for dynamic and third-party content.

# Evidence

- GSC: no query rows in the current export.
- Primary sources: Squarespace lists Email Campaigns, Acuity Scheduling, third-party blocks, Member Sites and customer login screens as unsupported. Weglot documents dynamic selectors for content generated after the initial page parse.

# Existing URL decision

- Create `/what-weglot-does-not-translate-squarespace/`.
- Keep separate from the checkout/forms/emails guide, which owns the end-to-end transaction journey.

# Solution structure

1. Separate known unsupported Squarespace services from site-specific content that needs testing.
2. Give a page-by-page audit method.
3. Explain dynamic selectors without promising they solve third-party services.
4. Provide decision rules for Weglot, Multilingualizer and manual Squarespace pages.

# Product fit and CTA

- Weglot for broad managed translation after the gaps are accepted.
- Multilingualizer one-time option for manually supplied on-page translations, not protected checkout/account screens.

# Success metric

Impressions for limitation queries, calculator starts and product/affiliate clicks.
