# Problem

An ecommerce or lead-generation site needs to know which parts of its real customer journey are translated.

# Evidence

- GSC: no query rows in the current export.
- Primary sources: Squarespace documents translated customer notifications, unsupported services and language settings. Weglot documents dynamic content selectors.

# Existing URL decision

- Create `/weglot-squarespace-checkout-forms-emails/`.
- Keep separate from the broader translation-gaps page because this intent is transactional and requires a test matrix.

# Solution structure

1. Map owner and translation behaviour for checkout, form, confirmation, account and email steps.
2. Test product names, validation, discounts, taxes, shipping and notifications.
3. Explain what dynamic rules can and cannot cover.
4. Give a pre-purchase decision.

# Product fit and CTA

- Weglot is preferred where the documented commerce email workflow is required.
- Multilingualizer callout must state that it does not translate protected checkout/account screens.
- Multicurrencyalizer is relevant only after its current behaviour is verified.

# Success metric

Qualified affiliate clicks and lower exits from ecommerce readers.
